# Family Finance 3.3

Семейный финансовый учёт: Семья, Маркетинг, НЗ, Инвестиции. FastAPI, SQLite, адаптивный HTML/CSS/JavaScript. Импорт SMS Приорбанка, классификация, переводы, категории, аналитика, валютные эквиваленты НБРБ и ручная оценка инвестиционного портфеля.

## Обновление на Railway (с 3.0–3.2)

Замените исходники сервиса содержимым этого проекта и выполните redeploy. При обновлении с 3.2 добавляется таблица распределения категорий по лимитам; существующие финансовые данные сохраняются. Сохраните существующий Volume и DATABASE_PATH (например `/data/finance-v3.db`). База обновляется автоматически: добавляется период лимита и отдельная очередь уведомлений о покупках. Старые лимиты остаются месячными до редактирования; новые по умолчанию недельные. Старые операции, категории, оценки и правила не удаляются. Старые неотправленные пороговые уведомления больше не отправляются. Сделайте резервную копию SQLite перед обновлением (при остановленном сервисе).

Переменные: API_SECRET (прежний ключ SMS), WEB_USERNAME (по умолчанию family), WEB_PASSWORD (отдельный пароль, иначе API_SECRET), TELEGRAM_BOT_TOKEN, TELEGRAM_CHAT_ID, TELEGRAM_WEBHOOK_SECRET (секрет webhook; при отсутствии вычисляется отдельный секрет), APP_BASE_URL (публичный HTTPS URL), DATABASE_PATH (путь на Volume). Для входа через Telegram добавьте ALLOWED_TELEGRAM_USER_IDS; для обычного браузера новые переменные не требуются. Один экземпляр сервиса; очередь Telegram обрабатывается примерно каждые 30 секунд.

## Автоматический вход в Telegram Mini App (3.2)

1. В Railway → Variables добавьте `ALLOWED_TELEGRAM_USER_IDS=123456789,987654321`, подставив реальные числовые Telegram **user ID** каждого разрешённого пользователя. ID можно узнать из поля `message.from.id` обновления Telegram Bot API, когда пользователь отправляет боту сообщение. При пустом списке автоматический вход отключён. ID группового чата (`-100…`) не является ID пользователя.
2. Сохраните прежние `API_SECRET`, `WEB_USERNAME`, `WEB_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `APP_BASE_URL` и `DATABASE_PATH`. `APP_BASE_URL` должен быть публичным HTTPS-адресом приложения без пути (например `https://my-finance.up.railway.app`).
3. В @BotFather выполните `/setmenubutton`, выберите существующего бота и укажите URL `https://my-finance.up.railway.app/mini` (замените домен своим), затем название кнопки «Мои финансы». Это постоянная кнопка запуска Mini App в личном чате с ботом.
4. После redeploy нажмите новую кнопку. Если Telegram передал действительные подписанные данные разрешённого аккаунта, приложение создаст сессию и откроется без пароля. При обычном переходе в браузере остаётся форма логина/пароля с cookie на 30 дней. Внутри Telegram после «Выйти» автоматически повторно не авторизуем до нового запуска Mini App.

### Уведомления и семейный групповой чат

В личном чате с ботом (`TELEGRAM_CHAT_ID` — положительный числовой ID) новые уведомления автоматически получают inline `web_app`-кнопки «Разобрать операцию», «Открыть операцию» и «Посмотреть лимиты». Старые сообщения не редактируются. Для групп/каналов Telegram не поддерживает такие inline web_app-кнопки; по умолчанию будет обычная HTTPS-кнопка, открывающая сайт с обычной авторизацией.

Чтобы и в семейной группе вход работал без пароля, создайте именованное Mini App через @BotFather (`/newapp` → ваш существующий бот), задайте URL `https://my-finance.up.railway.app/mini` и короткое имя, например `finance`. Добавьте в Railway:

```env
TELEGRAM_BOT_USERNAME=your_finance_bot
TELEGRAM_MINI_APP_SHORT_NAME=finance
```

Без символа `@` в имени бота. После redeploy кнопки в группе используют `https://t.me/your_finance_bot/finance?startapp=tx_42` (ID операции передаётся автоматически) или `?startapp=limits`. Сервер получает подписанный Telegram `start_param` и открывает соответствующий экран. Оба пользователя должны быть в allowlist. Постоянная кнопка в личном чате работает независимо от этой дополнительной настройки. Telegram-аккаунты не получают отдельных финансовых баз: у разрешённых пользователей один общий семейный бюджет.

### Безопасность

Вход проверяет HMAC-SHA256 исходного `Telegram.WebApp.initData` по токену бота, время выдачи (не старше 5 минут, допуск 30 секунд вперёд) и user ID по allowlist. Неподписанный `initDataUnsafe`, простой ID, User-Agent или факт открытия ссылки внутри Telegram не дают доступа. Данные авторизации передаются в теле POST, не в URL. Cookie подписана, HttpOnly, SameSite=Lax, Secure при HTTPS. Удаление ID из списка или смена токена бота инвалидирует Telegram-сессии; смена пароля/API_SECRET инвалидирует все сессии. Выход удаляет cookie текущего браузера, а новый запуск Mini App может снова автоматически войти. Для публичного размещения используйте HTTPS и сильные разные секреты. Официальная документация: https://core.telegram.org/bots/webapps.

## Локальный запуск

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# заполните секреты в .env
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте http://127.0.0.1:8000. Вход через HTML-форму, подписанная HttpOnly cookie на 30 дней, Secure при HTTPS. При переходе из Telegram Mini App доступен автоматический вход; сохраняется ссылка на конкретную операцию. Выход — Настройки → Выйти. HTTP Basic сохранён для совместимости API. Используйте HTTPS в production; смена пароля или API_SECRET инвалидирует ранее выданные cookies. Выход удаляет cookie в текущем браузере.

Docker: `docker compose up -d --build`. Проверка: `/health`.

## Лимиты

Настройки → Лимиты → Новый лимит: недельный (суббота–пятница, Europe/Minsk) или календарный месячный. Выберите только нужные категории; родительская включает потомков. Несколько лимитов могут учитывать одну покупку, но отчёт не удваивает расход. Каждую субботу недельный остаток пересчитывается с нуля; перенос остатков отсутствует. Для недельного лимита дополнительно отображаются фактические расходы календарного месяца и ориентир = недельная сумма × число дней месяца / 7. Это информационная оценка, а не второй лимит. Отдельный месячный лимит можно создать независимо. Изменение настроек применяется к историческим расчётам с указанного месяца, версий лимитов нет.

Уведомление ставится в очередь после каждой учтённой покупки текущего периода, попадающей в лимит: покупка, период, потрачено, остаток, предупреждение при остатке <=30%, <=10%, нуле или перерасходе. Если покупка входит в несколько лимитов, по каждому своё сообщение. Повторная доставка SMS или повторное сохранение одной операции не создаёт дубликата для того же лимита. Исторические операции вне текущего периода не генерируют устаревшие уведомления. При ошибке доставки сообщение остаётся в очереди. Возвраты уменьшают расходы, но не создают уведомления о покупке.

## Банковские операции

Прежний POST /api/sms с Authorization: Bearer API_SECRET и JSON {"message":"...","device":"wife"}. При поступлении новой SMS бот отправляет кнопку открытия операции (Mini App в личном чате, либо именованное Mini App в группе при соответствующей настройке). На главной показан счётчик неразобранных операций; Операции → На разбор открывает все pending, без ограничения текущим месяцем. Нажмите «Разобрать», выберите тип, контур, категорию и сохраните. Можно запомнить магазин: последующие подходящие SMS автоматически классифицируются и сразу учитываются в лимитах. Снятие наличных/переводы между собственными картами можно отметить внутренними; перевод между контурами выбирается отдельно. Неизвестный курс не теряет SMS. Дубликаты SMS исключаются по нормализованному тексту.

## Аналитика и инвестиции

Выбирайте произвольный период и контур; недельная группировка начинается с субботы. Единая диаграмма распределяет доступные деньги (начальный остаток, начальные суммы за период, внешние доходы и входящие переводы) на расходы, исходящие переводы по контурам и конечный остаток. Два режима: по категориям и по лимитам. При выборе всех контуров внутренние переводы не включаются в диаграмму, поскольку деньги остаются внутри общей системы. Отрицательные суммы показаны отдельно в легенде; проценты секторов в этом случае рассчитываются от положительных сумм. Нажатие сектора раскрывает подкатегории и операции, а нажатие остатка — его расчёт. Учётная стоимость инвестиций в этой диаграмме не включает рыночную переоценку. Недельные расходы показываются отдельно для выбранного лимита и всех расходов. Инвестиции: внесено минус выведено = чистые вложения; вручную задавайте стоимость портфеля, приложение покажет прибыль и простую доходность. Валютные эквиваленты для НЗ, маркетинга и инвестиций используют текущие курсы НБРБ; это не отдельные валютные кошельки. Экспорт CSV доступен из операций.

Дополнительно проверены HMAC Telegram, allowlist, истечение initData, отзыв доступа, переход к операции и генерация кнопок личного/группового чата. ## Новое в 3.3

- Новые SMS в семейной группе имеют кнопки «Разобрать прямо в Telegram» и «Открыть в приложении». Прямой разбор доступен разрешённым Telegram user ID в настроенном чате: тип, контур, категория/подкатегория, подтверждение, сохранение правила магазина. Повторное подтверждение не учитывает покупку дважды. `/pending` повторно выводит до 10 ожидающих банковских операций; полный список доступен в приложении. Для команд в группе можно использовать `/pending@financefamily_bot` (подставьте реальное имя бота).
- Webhook регистрируется автоматически при старте сервиса, повторяется при ошибке. Укажите публичный HTTPS `APP_BASE_URL` либо подключите публичный домен Railway. Если `TELEGRAM_WEBHOOK_SECRET` задан, используйте 1–256 символов A–Z/a–z/0–9/underscore/hyphen. При пустом или недопустимом значении сервер вычисляет отдельный секрет.
- Если в группе настроено именованное Mini App через BotFather `/newapp`, кнопка использует ссылку `https://t.me/<bot>/<short_name>?startapp=tx_<id>`. Иначе открывается обычная HTTPS-ссылка на операцию.
- Настройки → Распределение: категории могут входить в несколько независимых лимитов, но каждый расход на диаграмме относится только к одному. Можно выбрать основной лимит для диаграммы. По умолчанию наследуется допустимый выбор родителя; иначе предпочтение недельному лимиту, затем наиболее точной категории, затем первому созданному лимиту. Все недельные группы объединяются в один сектор с детализацией по лимитам. Категории вне лимитов остаются отдельными.
- Недельная статистика: реальные даты суббота–пятница, границы выбранного отчёта, все расходы, расходы в выбранных лимитах и вне них; детализация по нажатию.
- Мобильная верстка: поля даты на узких экранах в отдельных строках, модальные окна ограничены шириной экрана, текст и кнопки переносятся.
- Старые сообщения в Telegram не редактируются автоматически. Старые пороговые уведомления не повторяются; новые покупки используют очередь уведомлений 3.1+.
