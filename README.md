# Family Finance 3.0

Новая версия проекта семейного финансового учёта. Python / FastAPI / SQLite + адаптивный веб-интерфейс на HTML, CSS и JavaScript без сборки frontend. Сохранён парсер SMS Приорбанка и механизм курсов НБРБ. Telegram используется для уведомлений, а не для ведения диалогов.

## 1. Запуск с чистой базой

В архиве нет финансовой базы, секретов или старых операций. При первом запуске создаются новые таблицы `v3_*`, предустановленные справочные категории, четыре нулевых баланса и пустой список лимитов. Старая база не мигрирует и автоматически не удаляется. Используйте новый путь `finance-v3.db`, а прежний файл сохраните отдельно, если нужен резервный архив. При повторном запуске новые данные сохраняются.

### Локально

Требуется Python 3.11+ (Docker использует 3.13). В каталоге проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
openssl rand -hex 32
```

В `.env` задайте два разных надёжных секрета (`API_SECRET`, `WEB_PASSWORD`). `WEB_USERNAME` по умолчанию `family`. Если Telegram пока не нужен, оставьте токен и chat ID пустыми.

```bash
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000/`, введите `WEB_USERNAME` и `WEB_PASSWORD` в стандартном окне HTTP Basic. Для реального использования с телефона через Интернет обязательно HTTPS. Не публикуйте незашифрованный HTTP Basic наружу. Отдельных аккаунтов пользователей в этой версии нет: доступ к общему семейному бюджету по одному логину/паролю.

### Docker Compose

```bash
cp .env.example .env
# заполните .env
# затем
docker compose up -d --build
docker compose logs -f finance
```

Сервис слушает localhost:8000, база хранится в томе `finance_data`. Для внешнего доступа настройте HTTPS reverse proxy. Для создания резервной копии используйте SQLite backup API или остановите сервис перед копированием файла; CSV не содержит настройки и оценки инвестиций.

### Railway / сервер

- Разверните этот каталог через Dockerfile. Один экземпляр приложения / один Uvicorn worker: уведомления обслуживаются одним фоновым циклом.
- Подключите постоянный Volume (например `/data`). Укажите `DATABASE_PATH=/data/finance-v3.db`, либо используйте `RAILWAY_VOLUME_MOUNT_PATH` и не задавайте `DATABASE_PATH`.
- Установите `API_SECRET`, `WEB_USERNAME`, `WEB_PASSWORD`, при необходимости `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `TELEGRAM_WEBHOOK_SECRET`, `APP_BASE_URL=https://ваш-домен`.
- Проверка: `GET /health`. Веб-интерфейс: `/`. API: `/docs`.
- Dockerfile читает переменную `PORT` (по умолчанию 8000).
- Не запускайте несколько реплик с одной SQLite-базой. Для нескольких экземпляров потребуется централизованная БД и выделенный worker уведомлений.

## 2. Финансовая модель

Четыре контура: `family` (Семья), `marketing` (Маркетинг), `reserve` (НЗ), `investment` (Инвестиции). Это управленческие бюджеты, а не банковские счета.

- Доходы семьи: зарплата Кирилла, зарплата жены, детские, другие доходы. Маркетинг: доходы клиентов и другие доходы.
- Маркетинг: налог, зарплаты помощницам, расходы бизнеса.
- Любой контур может переводить средства в любой другой. Например, Маркетинг → Семья, Семья → НЗ, НЗ → Маркетинг, НЗ → Инвестиции, Инвестиции → Семья. Перевод записывается один раз и изменяет два баланса атомарно. В общем отчёте он не является внешним доходом или расходом.
- `opening` — начальный остаток на указанную дату, не считается доходом периода. `refund` — возврат в категорию расходов, уменьшает нетто-расходы. `internal` — снятие наличных или перемещение между собственными картами внутри одного контура, не меняет управленческий баланс.
- При импорте SMS операция обычно находится на разборе (`pending`). Баланс и лимиты меняются после классификации (`posted`). Исключённая операция (`ignored`) не учитывается, её можно вернуть через редактирование.
- Все суммы хранятся целыми числами в копейках; расчёты валют используют Decimal. В API поля `amount`/`original` в ответах транзакций и агрегированные суммы — в копейках; запросы создания/редактирования принимают обычные денежные суммы (например `50.25`).
- Отрицательные балансы разрешены, чтобы не блокировать внесение операций задним числом. Приложение не сверяет фактический банковский остаток автоматически.

## 3. Как пользоваться веб-интерфейсом

Главная: четыре баланса, оценка инвестиций, операции на разбор, карточки месячных лимитов. Для маркетинга, НЗ и инвестиций показываются эквиваленты EUR, USD и RUB по официальному курсу НБРБ на текущую дату. Это справочные эквиваленты, не фактические остатки в отдельных валютах. Если курс недоступен, он не выдумывается.

Операция: верхняя кнопка «＋ Операция». Укажите тип, контур, категорию или контур назначения, сумму, валюту, дату, комментарий. Можно записывать операции задним числом и редактировать их. Для маркетинговых клиентов можно создать отдельные подкатегории дохода.

Операции: фильтр по датам, контуру и статусу, редактирование и исключение из расчётов, CSV. В статусе «На разбор» показываются все ожидающие операции независимо от выбранных дат. SMS-операцию можно классифицировать и запомнить магазин. Правила действуют на точное нормализованное название магазина для последующих банковских покупок; поступления денег требуют ручного разбора, чтобы не перепутать зарплаты и переводы.

Настройки → Категории: добавление категорий и подкатегорий, изменение названия и родителя, архивирование. Контур и тип существующей категории нельзя менять, чтобы не нарушать исторические операции. Архивные категории остаются в истории.

Аналитика: произвольный период, текущий/предыдущий календарный месяц или последние 7 дней; фильтр по контуру. Доходы, расходы нетто, входящие/исходящие переводы, начальный/конечный учётный остаток. Нажмите сектор круговой диаграммы либо категорию в легенде: откроются операции выбранной категории вместе с подкатегориями. Есть разбивка по источникам доходов, недельные расходы и журнал движения денег. В графике недель можно выбрать конкретный лимит или объединение активных лимитов без двойного счёта. Недельные интервалы начинаются в понедельник, на границе периода берутся только выбранные даты. Возвраты уменьшают расходы; отрицательные нетто-категории остаются в легенде, но не формируют сектор окружности.

## 4. Лимиты

Настройки → Лимиты → «＋ Лимит».

Пример общего лимита:

- Название: Повседневные траты.
- Контур: Семья.
- Сумма: 500 BYN.
- Выберите «Еда» (включая Продукты, Кафе, Доставку), «Развлечения», «Игрушки». Не выбирайте Одежду, Ремонт авто и остальные категории, которые не должны уменьшать этот лимит.

Пример дополнительного лимита:

- Название: Игрушки Герману.
- Сумма: 50 BYN.
- Выберите соответствующую подкатегорию (при необходимости создайте её).

Лимиты независимы: покупка игрушек 20 BYN может уменьшить одновременно остаток общего лимита и отдельного лимита игрушек, но в общей статистике расходы не удваиваются. Выбор родительской категории включает её потомков, в том числе созданных позднее. Если нужна только часть подкатегорий, отметьте именно их, а не родителя.

Месяц — календарный, с 1 числа, часовой пояс Europe/Minsk. Лимит повторяется ежемесячно начиная с указанного месяца. Неиспользованный остаток не переносится. Изменение суммы, состава или активного статуса лимита применяется к историческим отчётам с месяца начала действия; отдельных версий бюджета на каждый месяц пока нет.

Telegram-уведомления отправляются при расходовании 70% (осталось 30%), 90% (осталось 10%) и превышении 100% (перерасход). При точном достижении 100% показывается нулевой остаток в интерфейсе; уведомление о перерасходе появляется при превышении. Каждый порог срабатывает один раз за календарный месяц для каждого лимита. Если одна операция пересекает несколько порогов, формируются все соответствующие уведомления. Изменение/возврат не переотправляет уже сработавший порог.

Очередь уведомлений хранится в SQLite. Worker проверяет её примерно раз в 30 секунд, при ошибке отправки повторяет попытку. Доставка рассчитана на один экземпляр сервиса; при аварийном завершении сразу после успешной отправки возможна повторная доставка.

## 5. Инвестиции

Пополнение: операция «Перевод» из Семьи, Маркетинга или НЗ в Инвестиции. Прямое внешнее поступление в инвестиционный контур считается дополнительным взносом. Вывод: перевод из Инвестиций в другой контур. Начальный остаток в Инвестициях тоже считается внесённым капиталом.

На главной выберите «Обновить оценку». Введите фактическую стоимость портфеля на дату оценки (BYN, USD, EUR или RUB). Валютная оценка конвертируется по курсу на выбранную дату. Она не создаёт доход или расход и не изменяет остальные контуры. Стоимость обновляется вручную; котировки акций не запрашиваются.

- Чистые вложения = все взносы − выводы.
- Результат = текущая рыночная стоимость − чистые вложения.
- Доходность = результат / чистые вложения × 100%.
- Стоимость к вложениям = текущая стоимость / чистые вложения × 100%.
- Если чистые вложения <= 0, проценты не рассчитываются (показывается абсолютный результат).

Пример: внесено 1 000 BYN, текущая стоимость 1 200 BYN → +200 BYN, +20%, стоимость 120% от чистых вложений. Если после оценки внесено ещё 300 BYN, оценка корректируется до 1 500 BYN без искусственной прибыли. Изменение рыночной цены нужно вводить вручную. Это простая доходность относительно чистого капитала, не годовая и не TWR/XIRR. Если задним числом исправлялись операции, оценку портфеля желательно обновить для сверки.

## 6. Банковские SMS и Telegram

Существующая автоматизация iPhone может продолжать отправлять сообщения на тот же endpoint:

```http
POST /api/sms
Authorization: Bearer <API_SECRET>
Content-Type: application/json
```

```json
{"message":"Karta 4***1234 14-11-26 10:34:07. Oplata 42.00 BYN. BLR TEST SHOP. Balance: 200.00 BYN","device":"phone1"}
```

Парсер Приорбанка сохранён; поддерживаются платежи, пополнения, переводы, снятие наличных, OTP игнорируется. Хеш нормализованного SMS предотвращает повторный импорт одного сообщения даже с разных устройств. При недоступном валютном курсе SMS сохраняется в ожидающих операциях, а worker пытается получить курс примерно каждые пять минут. Ручное сохранение валютной операции требует доступного курса.

Telegram присылает сообщение о новой банковской операции с суммой, датой и ссылкой на разбор в веб-интерфейсе (если задан `APP_BASE_URL`), а также уведомления о лимитах. Старые команды и inline-кнопки классификации больше не используются. Старый `/telegram/webhook` принимает только запросы с секретом и не выполняет команд. Новый webhook регистрировать не требуется, поскольку сообщения отправляются напрямую Bot API. Если на старом боте остались команды и кнопки, они неактивны; можно удалить старый webhook через Telegram Bot API, но это не требуется для исходящих сообщений.

**Внимание:** автоматическое сопоставление двух SMS для одного перевода между собственными картами не реализовано. Если движение уже отражено вручную или другим SMS, второе сообщение отметьте как внутреннее/исключите из учёта. Правила магазинов не применяются к банковским переводам и снятию наличных.

## 7. API и структура

- `app/main.py`: FastAPI, HTTP Basic, endpoints, SMS, Telegram-уведомления.
- `app/ledger.py`: SQLite, финансовые операции, остатки, лимиты, отчёты, оценка портфеля.
- `app/parser.py`: исходный парсер SMS Приорбанка.
- `app/exchange.py`: исходный клиент НБРБ с историческими курсами и нормализацией `Cur_Scale` (например RUB).
- `app/categories.py`: начальный справочник; после инициализации категории редактируются в БД.
- `app/static/`: веб-интерфейс.
- `tests/`: тесты парсера и новой бизнес-логики.

Endpoints: `/api/dashboard`, `/api/categories`, `/api/transactions`, `/api/limits`, `/api/limits/all`, `/api/investment/valuation`, `/api/report`, `/api/export.csv`, `/api/sms`, `/health`. CRUD-операции веб-интерфейса защищены HTTP Basic; SMS защищён Bearer. Экспорт принимает веб-авторизацию или Bearer для совместимости с прежней интеграцией.

## 8. Тестирование

```bash
pip install -r requirements-dev.txt
python -m pytest -q
node --check app/static/app.js  # необязательно, если установлен Node.js
```

Тесты используют временные базы и подменённые валютные курсы / Telegram. Они не создают реальные финансовые операции и не отправляют реальные сообщения. Реальный Telegram, iPhone Shortcut, HTTPS и курс НБРБ необходимо проверить после настройки окружения. Автоматическая проверка мобильного браузера в среде сборки ограничена политикой Chromium; синтаксис JS проверен отдельно.
